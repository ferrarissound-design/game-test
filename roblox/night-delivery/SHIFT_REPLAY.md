# 夜勤の装備と自己記録

## 操作とルール

配達所の受注ボードで、依頼候補を見ながら無料の装備を1つ選びます。
最初の依頼を受けると、その夜勤の6件を終えるまで固定されます。
候補画面を閉じるだけでは装備は確定しません。次の夜勤では選び直せます。

| 装備 | 効果 |
| --- | --- |
| 保温ライナー | 温かい料理の品質期限30→40秒、冷凍便35→45秒。配達期限とS/A/B/C評価の時間基準は既存のまま |
| 緩衝パッド | ワレモノ便の空中移動を1回だけ保護。ジャンプから着地までを1回として数える。2回目以降は既存の破損扱い |
| 検品メモ | 高級品の追加報酬をB評価以上から獲得。S/A/B/C評価自体は変えない |

装備は荷物ごとの条件にだけ作用します。バッグの積載量強化、大型荷物の自転車禁止、
アスレチック配達先の貨物制限、追加配達の残件数制限、既存の報酬計算をそのまま使います。
FINAL RUNは既存の集計箇所で1回だけ倍率を計算します。
スマホでは省略表示される荷物説明に加えて、荷物タイトルにも有効な装備条件を表示します。

## 記録

- 6件を完了した夜勤だけ、前回と自己ベストを更新します。途中退出では記録を更新しません。
- Perfect件数と、6件の配達計測時間の合計を比較します。
- 計測時間はルート確定から配達まで。受注・ルート選択・配達所へ戻る時間は含みません。
- 配達先・天候・速度強化・追加便などが違うため、時間は条件別ランキングではなく参考記録です。
- 初回は比較基準を作り、次回以降は前回との差と自己ベスト、次の目標を表示します。
- `shiftRecord` を既存のプレイヤーDataStoreペイロードに追加。既存データにフィールドがなくても動作します。
- 装備選択は夜勤単位のセッション状態です。別サーバーへの参加時は初期装備に戻ります。

## 自動テスト

`roblox/night-delivery` で実行します。

```sh
python -m pip install lupa tree-sitter tree-sitter-luau
python -m unittest discover -s tests -v
```

Luau構文、Rojoマッピング、品質期限の境界、空中移動の1回保護、
高級品条件、FINAL RUNの二重加算防止、完了時だけの記録更新、再読込、
装備の途中変更・不正値・遠隔受注の拒否、次の夜勤のフェーズを検証します。
サーバー関数は小さなRobloxモック内で実行し、Luauの複合代入だけをLua向けに変換します。

## Studio / スマホでの確認項目（未実施）

1. 縦画面・横画面で装備の44pxボタンと依頼一覧のスクロールを確認。
2. 各装備を選び、2件目以降に変更できず、夜勤完了後は変更できることを確認。
3. 緩衝パッドでジャンプ1回→着地→2回目、および配達中のリスポーンを確認。
4. 6件完了を2回行い、前回差・自己ベスト・目標表示と結果画面の閉じる操作を確認。
5. セーブ可能なテスト環境で再参加し、記録が残ることを確認。
6. 複数人、追加便、FINAL RUN、天候、特殊配達を併用して既存の夜勤進行を確認。

## 配達員の記録（今回追加）

- 既存の `ShiftWins` を夜勤完走回数として使い、2 / 5 / 12 / 25夜で称号を上げる。古いセーブにも過去の完走数を反映する。自転車の既存カラーや強化値を変えず、車輪の反射板だけ称号に合わせて変える。
- 生成された街のIDを訪問時に記録し、6件の夜勤を終えた時だけその街の完走を記録する。全7街完走で図鑑内に「七つの夜を知る者」の称号を表示する。街の抽選と発生率は従来通り。
- 怪異は受注時ではなく怪異の配達成功時に発見済みにする。未発見の名称は伏せる。従来の怪異3種と一夜あたりの出現制限を維持する。
- DataStore `NightDeliveryPlayerData_v2` に `worldThemeProgress` と `oddityDiscovery` を追加。いずれも既存キーに対する任意の追加フィールドで、未設定・不正IDを安全に空の図鑑として読み込む。ランクは既存 `shiftWins` から導出し、別の二重カウンターを保存しない。完走時に追加保存し、従来の自動保存・退出時保存も継続。
- 結果画面の帰社ボタンは短い暗転の後にサーバーへ依頼する。受注中、残りの配達先がある時、夜勤結果が未確定の時はサーバーが拒否する。配達所の近くへ戻って通常の受注ボードを使う。
- 3件目にPerfect数と自己ベスト件数の短い通知を表示する。時間は条件が異なる参考記録のまま扱う。

### 追加で人間が確認する項目

1. iPhone縦画面で図鑑と結果のスクロール、44px以上のボタン、標準操作UIとの位置関係を確認。
2. 異なる街を訪問・完走して再参加し、訪問/完走/未発見の表示が保存されるか確認。
3. 怪異配達の成功と途中退出をそれぞれ試し、成功した種類だけ登録されるか確認。
4. 完走後の帰社暗転、配達所での再受注、自転車利用中の帰社、2人での同時完走を確認。
5. 既存のセーブデータで称号が `ShiftWins` に応じて付与され、バッグと自転車の購入済みスタイル・積載量が維持されるか確認。
